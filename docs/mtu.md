# 设置 MTU 值

KCPTube 的 mtu 有两个设置参数，分别是 `mtu` 以及 `kcp_mtu`。只需要设置其中一个即可。如果两个都设置了数值，程序会用 `mtu` 按下方公式重新计算并**覆盖** `kcp_mtu`，即实际以 `mtu` 的换算结果为准（这一点与上游旧文档的描述相反，以代码行为为准，Rust 版与 C++ 版一致）。

`mtu` 表示的是，当前网络的实际 MTU 值。若要使用，请先自行测量所在网络的 MTU 值。设置后，KCPTube 会自行算出 kcp_mtu 的值。

`kcp_mtu` 表示的是 ikcp 内 mtu 变量的值。亦即 UDP 包内数据的大小。

两个都不设置时，kcp_mtu 取默认值：

| 场景 | kcp_mtu 默认值 |
|---|---|
| 不使用 FEC | 1418 |
| 启用 FEC | 1405 |

## mtu 如何换算成 kcp_mtu

设置了 `mtu` 时，程序按下式自动计算：

```text
kcp_mtu = mtu - 加密预留 - 头部开销
```

- **加密预留**：
    - 使用加密（填写了 `encryption_password`）：48 字节
    - 不使用加密：2 字节（校验码）
- **头部开销**：
    - 不使用 FEC：4 字节
    - 使用 FEC：56 字节（含 IP / UDP / 数据层 / FEC 头）
- 若启用 `mux_tunnels`，再额外减 4 字节。

示例：

| mtu | 加密 | FEC | mux | kcp_mtu |
|---|---|---|---|---|
| 1500 | 是 | 否 | 否 | 1448 |
| 1500 | 否 | 否 | 否 | 1494 |
| 1500 | 是 | `20:4` | 否 | 1396 |
| 1400 | 否 | `10:3` | 否 | 1342 |
| 1500 | 是 | 否 | 3 | 1444 |

换算结果若不大于 0，会回落到上表的默认值。

## KCPTube 通道内转发 VPN

如果想减少数据包流量拆分，使每次发送的数据刚好匹配 MTU 值，最省事的做法是：测量网络实际 MTU 后直接填 `mtu`，让程序自动换算。

若希望自己指定 `kcp_mtu`，请参考以下开销，从 MTU 中减去相应数值：

KCP 数据头占用 24 字节。

KCPTube 自身数据头占用 4 字节（启用 FEC 时为 15 字节：13 字节 FEC 头 + 2 字节容器头）。

若启用 mux_tunnels 选项，会额外占用 4 字节。

若启用加密，会增加 48 字节（AEAD 预留）。

若不启用加密，则只增加 2 字节用于校验和。

> 说明：以上开销数值以 Rust 版代码为准（与 C++ 版 20260329 的包层常量一致），与上游旧文档中的示例数值略有出入。
